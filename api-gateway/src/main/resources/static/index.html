RF06 a RF12

      
Despachar

      

        
API

        
POST /api/ocorrencias/{id}/despachos e GET /api/ocorrencias/{id}

        
Gera

        
MS-Ocorrencias publica saga.alocar-ambulancia. MS-Frota responde em saga.ambulancia-alocada. MS-Ocorrencias publica saga.reservar-leito. MS-Leitos responde em saga.leito-reservado.

        
Consome

        
MS-Frota, MS-Leitos e MS-Ocorrencias, nessa ordem. No sucesso, MS-Ocorrencias publica saga.atualizar-ambulancia e notificacao.registrar, consumidas por MS-Frota e MS-Notificacoes.

      

      
      

        
        
      

      
O 202 só diz que a saga começou. A tela consulta de novo a cada 2 segundos, por até 15 segundos.

RF24

      
Notificações

      

        
API

        
GET /api/notificacoes?ocorrenciaId=

        
Gera

        
MS-Ocorrencias ou MS-Leitos publicam notificacao.registrar.

        
Consome

        
MS-Notificacoes grava no Mongo e devolve a lista. API Gateway encaminha a consulta.

      

      
      

    


    

      
Critério 6

      
Prazo do aceite

      

        
API

        
GET /api/notificacoes?ocorrenciaId= depois dos 2 minutos.

        
Gera

        
O job do MS-Leitos lê o MySQL. Reserva confirmada não publica saga.leito-expirado.

        
Consome

        
MS-Notificacoes só recebe EXPIRACAO quando o prazo vence uma reserva sem confirmação.

      

      
Depois de um aceite, espere 2 minutos. A reserva confirmada não gera EXPIRACAO.

      
      
Marcador parado.

    


    

      
RF22

      
Outro leito

      

        
API

        
POST /api/leitos/demonstracao/leito-extra e DELETE /api/leitos/demonstracao/leito-extra/L-UTI-03

        
Gera

        
MS-Leitos cria ou remove o leito e apaga o cache da especialidade.

        
Consome

        
Na recusa, MS-Ocorrencias publica saga.reservar-leito e MS-Leitos prefere o outro leito livre.

      

      
Cria L-UTI-03 livre. Na recusa de L-UTI-01, a busca seguinte prefere esse código. Apague quando voltar a livre.

      

        
        
      

      

    


    

      
RF23

      
Falta de leito

      

        
API

        
POST /api/leitos/demonstracao/proxima-busca-sem-vaga

        
Gera

        
MS-Leitos, na tentativa seguinte, publica saga.leito-reservado com SEM_LEITO_COMPATIVEL.

        
Consome

        
MS-Ocorrencias publica notificacao.registrar do tipo FALTA_LEITO. MS-Notificacoes grava.

      

      
Arme a trava, deixe o hospital em recusa e despache uma UTI. A tentativa 1 reserva. A seguinte grava FALTA_LEITO. A trava vale uma vez e nasce desligada.

      
      

    


    

      
RF05

      
Circuito

      

        
API

        
GET /api/leitos/disponiveis e POST /api/ocorrencias

        
Gera

        
Com o MS-Leitos parado, o API Gateway responde 503. A abertura continua no MS-Ocorrencias.

        
Consome

        
O circuito vale só para /api/leitos. Login, abertura e despacho não entram nele.

      

      
Pare só o processo da porta 8095 com Ctrl+C. A consulta de UTI deve responder 503. A abertura, no mesmo momento, responde 201. Suba o MS-Leitos de novo.

      

        
        
      

      

    


    

      
Carga

      
Estado inicial

      

        
API

        
POST /api/ocorrencias/
demonstracao/reinicio
POST /api/ambulancias/
demonstracao/reinicio
POST /api/leitos/
demonstracao/reinicio
POST /api/notificacoes/
demonstracao/reinicio

        
Gera

        
MS-Ocorrencias apaga as ocorrências e esvazia as filas. MS-Frota devolve as ambulâncias a DISPONIVEL. MS-Leitos restaura os seis leitos da carga, apaga o extra e volta o modo a aleatório. MS-Notificacoes esvazia o Mongo.

        
Consome

        
API Gateway encaminha. O login do regulador permanece. Os processos Java continuam no ar.

      

      
Use com a saga parada. O botão não encerra serviço nem recria o banco do zero.

      
      

    


    

      
RabbitMQ

      
Filas

      

        
API

        
POST /api/ocorrencias/demonstracao/rajada
POST /api/ocorrencias/demonstracao/filas/acumulo
POST /api/ocorrencias/demonstracao/filas/esvaziar

        
Gera

        
A rajada abre e despacha pela saga. O acúmulo publica nas oito filas com os listeners pausados.

        
Consome

        
Na rajada, MS-Frota, MS-Leitos e MS-Notificacoes. No acúmulo, ninguém consome até esvaziar e religar.

      

      
Abra http://localhost:15672 e atualize Queues. A rajada gasta a carga. O acúmulo deixa Ready parado para a foto e não processa essas mensagens.
